Vesta

تخزين كائنات متوافق مع S3 يسدّ الثغرات · الإصدار 0.1.0

نظام تخزين كائنات طبقي متوافق مع S3، مكتوب بلغة Rust — ملف تنفيذي واحد يتوسّع من حاسوب محمول إلى عنقود مُكرَّر عبر Raft، دون الحاجة لتغيير البرمجية.

**هل تطوّر باستخدام الذكاء الاصطناعي؟** أعطِ وكيل البرمجة/نموذج اللغة الخاص بك هذا الرابط بدلًا من هذه الصفحة — مرجع كثيف ومُحسَّن للآلة (التثبيت، كل متغير بيئة وقيمته الافتراضية، استدعاءات API الدقيقة) يمكنه استخدامه مباشرة، دون الحاجة لاستنتاج الحقائق من نص تسويقي: [documentation.ai.md](https://iwasoft.com/products/vesta/0.1.0/docs/documentation.ai.md)

## ما هو Vesta

يستهدف Vesta الثغرات الوظيفية الموجودة في حلول تخزين الكائنات الحالية (S3، GCS، Azure Blob، R2، B2، Wasabi، MinIO، Ceph، SeaweedFS، Garage). يتحدّث واجهة S3 الحقيقية — توقيع SigV4، التحميل متعدد الأجزاء، الإصدارات، الطلبات الشرطية، الحذف الجماعي — ويفصل تمامًا بين **مستوى التحكم** (البيانات الوصفية: الدِلاء، فهرس الكائنات، إدارة الهوية) و**مستوى البيانات** (الكتل المخزّنة على القرص والمعنونة بالمحتوى)، بحيث يمكن استبدال كل منهما أو توسيعه بشكل مستقل.

## مبادئ التصميم

**الفصل بين مستوى التحكم ومستوى البيانات.**  
تعيش البيانات الوصفية والبايتات خلف حدود trait منفصلة. يمكن استبدال محركات التخزين وخلفيات الإجماع وطبقات التشفير دون المساس بطبقة واجهة S3.

**لا يبقى أي مفتاح إداري منسيًا في ملف إعداد.**  
تحديد المعدل، فترات تنظيف الكتل (GC)، CORS، الحصص والسياسات كلها إعدادات زمن-تشغيل — تُكرَّر وتُعدَّل حيًّا من لوحة الإدارة، وليست متغيرات بيئة تتطلب إعادة تشغيل.

**التوافق عقد، لا تقريب.**  
يُختبر SigV4 (الترويسات، روابط URL الموقّعة مسبقًا، الأجزاء المتدفّقة)، والتحميل متعدد الأجزاء، والإصدارات، والطلبات الشرطية باستمرار مقابل مجموعات اختبار حقيقية من SDK الخاص بـ AWS، لا أمثلة مُنتقاة يدويًا.

## بداية سريعة

شغّل الخادم (صورة حاوية، أو الملف التنفيذي المستقل):

```
# Docker
docker run -p 9000:9000 iwasoftcom/vesta:0.1.0

# أو الملف التنفيذي
VESTA_DATA_DIR=/var/lib/vesta vesta
```

تواصل معه باستخدام أي عميل S3:

```
aws --endpoint-url http://127.0.0.1:9000 s3 mb s3://photos
aws --endpoint-url http://127.0.0.1:9000 s3 cp ./x.jpg s3://photos/x.jpg
aws --endpoint-url http://127.0.0.1:9000 s3 ls s3://photos
```

## ما بداخله

**تحديد المعدل**  
دلو رموز لكل مستأجر، يُفعَّل ويُضبَط حيًّا من لوحة الإدارة؛ العميل المسيء يحصل على استجابة `SlowDown` نظيفة، لا اتصالًا مقطوعًا.

**الإجماع الموزَّع**  
Raft عبر الشبكة بانتخاب قائد، وعضوية ديناميكية، وتكرار دائم للسجل — أو اختر `openraft`، وهو تطبيق مُثبَت، خلف مسار الكتابة ذاته.

**ترميز المحو والتشفير**  
تخزين مُرمَّز بالمحو بطريقة Reed–Solomon وتشفير AES-256-GCM أثناء الخزن، وكلاهما آمن مع إزالة التكرار (كتل معنونة بالمحتوى).

**الإصدارات وقفل الكائن**  
سجل إصدارات كامل، علامات حذف، واحتفاظ WORM (GOVERNANCE/COMPLIANCE) مع حجز قانوني.

**تعدد المستأجرين**  
المستأجرون كيان أساسي: حصص دِلاء لكل مستأجر، عزل هوية عبر SigV4، سياسات الدِلاء وقوائم تحكم وصول جاهزة.

**البحث و Select و Lambda**  
بحث أصلي في البيانات الوصفية بفهرس معكوس، و S3 Select (SQL على CSV)، وتحويل عند القراءة (على طراز Object Lambda).

**التكرار والأحداث**  
تكرار جغرافي غير متزامن، ناقل أحداث لتدفق التغييرات، وتسليم إشعارات عبر webhook قابل للتوصيل.

**دورة الحياة والجرد**  
قواعد انتهاء الصلاحية والانتقال بين فئات التخزين، إضافة إلى تقارير جرد بصيغة CSV عند الطلب.

## لوحة الإدارة

تطبيق إداري منفصل وعديم الحالة (واجهة React + MUI مدمجة) يُمرِّر عمليات الكتابة إلى عقدة تخزين — لا يحتفظ ببياناته الخاصة؛ كل تغيير يُكرَّر عبر سجل الإجماع نفسه الذي تستخدمه واجهة S3.

<table><tbody><tr><th>العنوان</th><td><code>http://localhost:9500</code> (متغير البيئة <code>VESTA_ADMIN_ADDR</code>، الافتراضي <code>0.0.0.0:9500</code>)</td></tr><tr><th>يتصل بـ</th><td>واجهة إدارة عقدة تخزين، الافتراضي <code>http://127.0.0.1:9000</code> (متغير البيئة <code>VESTA_ADMIN_NODES</code>)</td></tr><tr><th>المستخدم الافتراضي</th><td>لا يوجد — تبقى اللوحة مفتوحة وتتصرف كمسؤول حتى يُنشأ <b>أول</b> مستخدم للوحة (شاشة المستخدمين)، وهو ما يغلق هذه النافذة. أو زوّدها مسبقًا عند إقلاع العقدة: <code>VESTA_ADMIN_USER</code>/<code>VESTA_ADMIN_PASS</code></td></tr></tbody></table>

تعرض كل عقدة أيضًا العمليات نفسها كواجهة JSON بسيطة على `http://<عقدة>:9000/_vesta/admin/*` (نفس النقاط التي تستدعيها اللوحة نفسها) — مفيدة للأتمتة عبر السكربتات. أول ثلاثة أشياء ستفعلها:

```
# 1) إنشاء دلو
curl -X POST http://127.0.0.1:9000/_vesta/admin/buckets \
  -H 'content-type: application/json' -d '{"name":"photos"}'

# 2) إنشاء مستأجر (مطلوب قبل مفتاح API)
curl -X POST http://127.0.0.1:9000/_vesta/admin/tenants \
  -H 'content-type: application/json' -d '{"name":"acme-corp"}'

# 3) إنشاء مفتاح API (زوج access/secret عبر SigV4) لهذا المستأجر
curl -X POST http://127.0.0.1:9000/_vesta/admin/keys \
  -H 'content-type: application/json' -d '{"tenant":"acme-corp"}'
# → {"access_key":"VESTA...","secret_key":"...","tenant":"acme-corp"}
```

بمجرد وجود مستخدم للوحة أو مفتاح API، تحتاج هذه الاستدعاءات إلى ترويستي `x-vesta-user`/`x-vesta-pass` (بيانات اعتماد مستخدم اللوحة) — وإنشاء هذا المفتاح الأول يُفعِّل تلقائيًا إلزامية SigV4 لواجهة S3 على مستوى العنقود بأكمله، دون إعادة تشغيل.

-   **المستخدمون والمفاتيح والمستأجرون** — حسابات اللوحة، مفاتيح API عبر SigV4، حصص لكل مستأجر.
-   **الدِلاء والسياسات** — الإنشاء/الحذف، JSON لسياسة الدلو، مفاتيح القراءة العامة.
-   **العنقود** — سلامة العقد، إضافة/إزالة الأعضاء، مفاتيح الكتابة بالأقلية والتقليص التلقائي.
-   **إعدادات زمن التشغيل** — تحديد المعدل، فترة تنظيف الكتل، أصل CORS: تُعدَّل حيًّا، وتُكرَّر على كل عقدة، وتبقى دائمة عبر إعادة التشغيل.

## البنية

ملف تنفيذي واحد، بابان شبكيّان، وقاعدة طبقية صارمة: طبقة واجهة S3 لا تلمس التخزين مباشرة أبدًا — كل شيء يمرّ عبر المنسّق، وكل تغيير يجب أن يسري على مستوى العنقود بأكمله يمرّ عبر سجل الإجماع قبل أن يصبح مرئيًا لعملية قراءة.

حزم S3 · aws-cli SigV4 · متعدد الأجزاء · الإصدارات لوحة الإدارة · وكلاء الذكاء الاصطناعي (MCP) وكيل عديم الحالة · أدوات مخصّصة للمستأجر واجهة S3 · :9000 واجهة الإدارة · :9500 المنسّق (Rust): الدِلاء · الكائنات · متعدد الأجزاء · السياسات · دورة الحياة · البحث سجل الإجماع (Raft خاص أو openraft) — تُثبَّت التغييرات قبل أن تصبح قابلة للقراءة البيانات الوصفية (WAL) · تخزين الكتل (مرمّز بالمحو، مشفّر، مُزال التكرار)

## التنزيلات والمصدر

-   **التنزيلات:** الملفات المُصرَّفة (Windows، Debian `.deb`، RedHat `.rpm`) وصورة Docker تُنشَر لكل إصدار على [iwasoft.com](https://iwasoft.com) ← المنتجات ← Vesta. الشيفرة المصدرية ليست جزءًا من التنزيلات.
-   **التوافق:** واجهة S3 (SigV4، متعدد الأجزاء، الإصدارات، الطلبات الشرطية) تُختبر باستمرار مقابل اختبارات تكامل حقيقية لـ SDK الخاص بـ AWS.
-   **حالة صادقة:** المشروع في مرحلة تطوير مبكرة — لم يخضع بعد لتدقيق أمني مستقل، ولا توجد بعد خبرة تشغيل إنتاجي. هذه إفصاحات، لا تحفظات على خارطة الطريق.
